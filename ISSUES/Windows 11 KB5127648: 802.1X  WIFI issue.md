# KB5127648 - NTLMv1 SSO / MS-CHAPv2 Compatibility Mitigation

## Overview

This document describes an enterprise mitigation for Windows devices affected by the NTLMv1-derived SSO hardening associated with **KB5127648 / October 2026 Windows security updates**.

In environments still using authentication methods such as **PEAP-MSCHAPv2**, **EAP-MSCHAPv2**, or other MS-CHAPv2-based network authentication, affected devices may experience authentication failures after the security update.

> **Important:** Setting `BlockNtlmv1SSO` to `0` is a temporary compatibility mitigation. It places the behavior in Audit mode rather than enforcing the newer security behavior. Long term, affected authentication dependencies should be removed.

---

## Symptoms

Potential symptoms include:

- Enterprise Wi-Fi authentication failure
- Wired 802.1X authentication failure
- PEAP-MSCHAPv2 authentication failure
- EAP-MSCHAPv2 authentication failure
- Some VPN authentication failures
- Connectivity working before the Windows security update and failing afterward

The presence of KB5127648 alone does not prove that every network authentication issue has this root cause. Validate the affected authentication method and registry state before broad deployment.

---

## Registry Setting

The mitigation explicitly configures:

```text
Registry Path : HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0
Value Name    : BlockNtlmv1SSO
Type          : REG_DWORD
Value         : 0
```

`0` represents the Audit-mode compatibility configuration used by this remediation.

# Microsoft Intune Remediation

## Recommended package name

```text

```

## Description

> Detects devices with KB5127648 installed and validates the BlockNtlmv1SSO registry configuration. If required, remediation configures BlockNtlmv1SSO as DWORD 0 to maintain the required compatibility behavior. The remediation verifies the resulting registry value and creates a local resolution marker.

# Detection Script

Detection behavior:

- KB5127648 not detected: compliant
- KB5127648 detected and `BlockNtlmv1SSO = REG_DWORD 0`: compliant
- KB5127648 detected and value is missing: non-compliant
- KB5127648 detected and value is not `0`: non-compliant
- KB5127648 detected and value has the wrong registry type: non-compliant

```powershell
$TargetKB      = "KB5127648"
$RegistryPath  = "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0"
$ValueName     = "BlockNtlmv1SSO"
$ExpectedValue = 0

Write-Output "============================================================"
Write-Output "KB5127648 / BlockNtlmv1SSO Detection"
Write-Output "============================================================"
Write-Output "Computer      : $env:COMPUTERNAME"
Write-Output "Target KB     : $TargetKB"
Write-Output "Registry Path : $RegistryPath"
Write-Output "Value Name    : $ValueName"
Write-Output "Expected      : REG_DWORD $ExpectedValue"
Write-Output "------------------------------------------------------------"

try {
    $HotFix = Get-HotFix -Id $TargetKB -ErrorAction SilentlyContinue

    if ($null -eq $HotFix) {
        Write-Output "Status        : COMPLIANT"
        Write-Output "KB Status     : NOT DETECTED"
        Write-Output "Registry Fix  : NOT REQUIRED BY THIS PACKAGE"
        exit 0
    }

    Write-Output "KB Status     : INSTALLED"

    if (-not (Test-Path -LiteralPath $RegistryPath)) {
        Write-Output "Status        : NON-COMPLIANT"
        Write-Output "Reason        : Registry path is missing."
        exit 1
    }

    $Key = Get-Item -LiteralPath $RegistryPath -ErrorAction Stop

    if ($Key.GetValueNames() -notcontains $ValueName) {
        Write-Output "Status        : NON-COMPLIANT"
        Write-Output "Current       : NOT CONFIGURED"
        Write-Output "Expected      : REG_DWORD $ExpectedValue"
        exit 1
    }

    $CurrentValue = $Key.GetValue(
        $ValueName,
        $null,
        [Microsoft.Win32.RegistryValueOptions]::DoNotExpandEnvironmentNames
    )

    $CurrentType = $Key.GetValueKind($ValueName)

    Write-Output "Current Type  : $CurrentType"
    Write-Output "Current Value : $CurrentValue"

    if ($CurrentType -ne [Microsoft.Win32.RegistryValueKind]::DWord) {
        Write-Output "Status        : NON-COMPLIANT"
        Write-Output "Reason        : Incorrect registry type."
        exit 1
    }

    if ([int]$CurrentValue -ne $ExpectedValue) {
        Write-Output "Status        : NON-COMPLIANT"
        Write-Output "Reason        : Incorrect registry value."
        exit 1
    }

    Write-Output "Status        : COMPLIANT"
    Write-Output "Registry Fix  : PRESENT AND VERIFIED"
    exit 0
}
catch {
    Write-Output "Status        : NON-COMPLIANT"
    Write-Output "Error         : $($_.Exception.Message)"
    exit 1
}
```

# Remediation Script

This remediation:

1. Ensures the registry path exists.
2. Creates or corrects `BlockNtlmv1SSO` as `REG_DWORD 0`.
3. Reads the value back to verify the change.
4. Creates a persistent local resolution marker.
5. Returns exit code `0` only after the registry configuration is verified.

```powershell
$RegistryPath  = "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0"
$ValueName     = "BlockNtlmv1SSO"
$DesiredValue  = 0
$MarkerFolder  = "C:\ProgramData\IntuneRemediation\KB5127648"
$MarkerFile    = Join-Path $MarkerFolder "KB5127648-Resolved.txt"

Write-Output "============================================================"
Write-Output "KB5127648 / BlockNtlmv1SSO Remediation"
Write-Output "============================================================"
Write-Output "Computer      : $env:COMPUTERNAME"
Write-Output "Registry Path : $RegistryPath"
Write-Output "Value Name    : $ValueName"
Write-Output "Desired       : REG_DWORD $DesiredValue"
Write-Output "------------------------------------------------------------"

try {
    if (-not (Test-Path -LiteralPath $RegistryPath)) {
        New-Item -Path $RegistryPath -Force -ErrorAction Stop | Out-Null
        Write-Output "[PASS] Registry path created."
    }
    else {
        Write-Output "[PASS] Registry path exists."
    }

    $Key = Get-Item -LiteralPath $RegistryPath -ErrorAction Stop
    $ValueExists = $Key.GetValueNames() -contains $ValueName

    if ($ValueExists) {
        $OldValue = $Key.GetValue($ValueName)
        $OldType  = $Key.GetValueKind($ValueName)
        Write-Output "Previous Type : $OldType"
        Write-Output "Previous Value: $OldValue"

        if ($OldType -ne [Microsoft.Win32.RegistryValueKind]::DWord) {
            Remove-ItemProperty -LiteralPath $RegistryPath -Name $ValueName -Force -ErrorAction Stop
        }
    }
    else {
        Write-Output "Previous Value: NOT CONFIGURED"
    }

    New-ItemProperty `
        -LiteralPath $RegistryPath `
        -Name $ValueName `
        -PropertyType DWord `
        -Value $DesiredValue `
        -Force `
        -ErrorAction Stop | Out-Null

    Write-Output "[PASS] Registry configuration applied."

    # Post-remediation validation
    $VerifiedKey = Get-Item -LiteralPath $RegistryPath -ErrorAction Stop
    $FinalValue  = $VerifiedKey.GetValue($ValueName)
    $FinalType   = $VerifiedKey.GetValueKind($ValueName)

    Write-Output "------------------------------------------------------------"
    Write-Output "POST-REMEDIATION VALIDATION"
    Write-Output "------------------------------------------------------------"
    Write-Output "Final Type    : $FinalType"
    Write-Output "Final Value   : $FinalValue"
    Write-Output "Expected Type : DWord"
    Write-Output "Expected Value: $DesiredValue"

    if ($FinalType -ne [Microsoft.Win32.RegistryValueKind]::DWord) {
        throw "Registry type validation failed."
    }

    if ([int]$FinalValue -ne $DesiredValue) {
        throw "Registry value validation failed."
    }

    # Create resolution marker
    if (-not (Test-Path -LiteralPath $MarkerFolder)) {
        New-Item -Path $MarkerFolder -ItemType Directory -Force -ErrorAction Stop | Out-Null
    }

    $ResolvedAt = Get-Date -Format "yyyy-MM-dd HH:mm:ss"

    $Marker = @"
============================================================
KB5127648 - BlockNtlmv1SSO Remediation Result
============================================================

Status          : RESOLVED
Computer Name   : $env:COMPUTERNAME
Resolution Date : $ResolvedAt
Registry Path   : HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0
Registry Value  : BlockNtlmv1SSO
Registry Type   : REG_DWORD
Registry Data   : 0

Result:
The required BlockNtlmv1SSO compatibility configuration was
successfully applied and verified by Microsoft Intune.

============================================================
"@

    Set-Content -LiteralPath $MarkerFile -Value $Marker -Encoding UTF8 -Force -ErrorAction Stop

    Write-Output "[PASS] Resolution marker created: $MarkerFile"
    Write-Output "============================================================"
    Write-Output "Status        : REMEDIATED AND VERIFIED"
    Write-Output "Exit Code     : 0"
    Write-Output "============================================================"
    exit 0
}
catch {
    Write-Output "============================================================"
    Write-Output "Status        : REMEDIATION FAILED"
    Write-Output "Error         : $($_.Exception.Message)"
    Write-Output "Exit Code     : 1"
    Write-Output "============================================================"
    exit 1
}
```

# Manual Fix

For a single test device, the same mitigation can be applied manually from an elevated PowerShell session:

```powershell
New-ItemProperty `
    -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0" `
    -Name "BlockNtlmv1SSO" `
    -PropertyType DWord `
    -Value 0 `
    -Force
```

Or Command Prompt:

```cmd
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0" /v BlockNtlmv1SSO /t REG_DWORD /d 0 /f
```

# Security Considerations

`BlockNtlmv1SSO = 0` should be regarded as a **temporary compatibility mitigation**, not a permanent target security state.

Where affected connectivity relies on legacy MS-CHAPv2/NTLMv1-derived authentication behavior, the strategic remediation should be to migrate away from that dependency. For enterprise 802.1X networks, certificate-based **EAP-TLS** is a better long-term design than permanently retaining PEAP-MSCHAPv2 compatibility behavior.

Before broad deployment:

1. Confirm the affected device has the relevant Windows update.
2. Confirm the authentication problem matches the NTLMv1/MS-CHAPv2 scenario.
3. Test the registry mitigation on a controlled Intune device group.
4. Monitor Wi-Fi, wired 802.1X, and VPN authentication after deployment.
5. Maintain a plan to migrate affected authentication to a modern method such as EAP-TLS.
